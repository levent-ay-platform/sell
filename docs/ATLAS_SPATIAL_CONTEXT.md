# Private Atlas spatial context
Under ATLAS MASTER #20. Existing pinned ODbL administrative geography (24 governorates, 279 delegations; see atlas-admin/SOURCE.md) is used without changing the originals. This is not a complete INS imada reference or cadastral survey.
Input: a private 0600 JSON object with kind PRIVATE_ATLAS_SOURCE_GEOMETRIES, crs EPSG:4326, public_export_permitted false, snapshot_sha256_private equal to the source registry snapshot, records_private. Each row has source_scoped_key [namespace,service_id,layer_id,object_id,version], geometry_kind CADASTRE_SOURCE / PLANNING_SOURCE / OTHER_SOURCE, and GeoJSON Polygon or MultiPolygon geometry. An operator must derive this input from actual reviewed source field mappings; never assign an arbitrary key to geometry. Non-WGS84 data needs an explicitly reviewed separate CRS transformation before input.
Run: python -m scripts.atlas_spatial_context --geometries PRIVATE_GEOMETRIES --registry PRIVATE_REGISTRY --graph PRIVATE_CANDIDATE_GRAPH --output PRIVATE_CONTEXT
The graph is the existing atlas_document_linkage output or the candidate_graph_private object extracted locally from the property index. Output binds input file SHA and pinned admin SHA, retains one row per supplied geometry (including missing/invalid), all positive-area intersections and zero-area contacts, and reports administrative parent conflicts. Areas computed in equal-area EPSG:6933; not survey-grade legal areas. Duplicate geometry keys suppress document association; source links remain candidates, never legal. Invalid administrative features are counted and not repaired silently. Counts include overlapping source rows, not unique land area or coverage. Source inputs need independent provenance review: matching keys and snapshot labels are not signatures of source authenticity. No public release or automatic app import.
Dependencies: pip install -r scripts/requirements-atlas-spatial.txt. The currently running 0fb0cae batch is unchanged. Synthetic tests plus pinned real reference asset test; actual local source geometry remains to be mapped.


## V7 optional sector and district context

The existing spatial-context command accepts optional `--sectors` and `--districts` paths to the exact audited public Map Tunisia medium-resolution GeoJSON files (commit `4f59a158faa5ed6fd3aa1a132e593ae3e94fda91`). The sectors file is byte-identical to the existing Android pinned reference; prepare it via the existing `scripts/prepare_amlak_admin_sectors.py` if needed. Districts are supplied separately. No downloads occur in the spatial-context CLI. Exact SHA-256, size, counts (2,083 upstream sectors and 5 districts), geometry validity and sector parent consistency are required. The upstream sector identifiers are not the Atlas INS 2024 crosswalk: 55 Atlas codes are unmatched, and 49 name-based candidates are not approved mappings. Neither the INS master nor the source asset is rewritten.

The output retains positive-area intersections and boundary-only contacts at the optional levels, records sector/delegation parent conflicts, and does not invent imada assignments when optional files are absent. Multiple intersecting boundaries remain multiple candidates. The original document graph, source identity, privacy, and legal verification rules are unchanged. ODbL attribution is recorded; keep open reference data separately licensed and do not publish a private derivative database automatically. These are context results only, not verified official plan/title/parcel relationships. The current production index and Amlak runtime are unchanged until separate real acceptance.
