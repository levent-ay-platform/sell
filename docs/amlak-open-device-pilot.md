# Open device Pilot — isolated QA only
Any valid Tunisian phone and fixed code 1234 can log in from a current device-key-capable Pilot. Each phone + random device key maps to its own account. No manual device enrollment. Do not use for real identity or title documents: this is not real phone authentication. Reinstalling/clearing app data loses the device key and creates a new account. Do not copy old accounts, sessions, evidence, keys or production admin credentials into this store. Existing database remains untouched and cannot be opened in the other mode.

Required runtime settings: MALAK_OPEN_DEVICE_PILOT=1, MALAK_PRIVATE_REVIEW_ATTACHMENTS=1, MALAK_DIRECT_PUBLISHING=0, MALAK_PILOT_DATA=<new dedicated test-only absolute directory>. Remove enrollment setting in the isolated runtime only. Private CRM Nozha plan still needs enrolled mode; approved public project card unaffected. No real publication, no automatic legal verification. The old database and its sessions will not be accessible through this open Pilot; retain the existing service for real data or plan a distinct QA endpoint. Do not cut over an active production service without checking impact and rollback.
