# Atlas private generation review
Part of existing PR #32 / ATLAS MASTER #20. This contract is not the installed catalogue writer.

1. Identify the actual catalogue producer and its active database from authorized local service configuration. Use its existing idle connection after commit with atlas_sqlite_snapshot.backup_from_producer_connection. Never retry a blocked live command by another transport, change ACLs, use immutable live SQLite, or run historical extraction again.
2. Provide the accepted baseline and fresh owner-authorized standalone backups, each with the original paired proof. A historical main-file diagnostic does not meet this contract. Do not manufacture a proof for older data. If the accepted 64,397 historical page rows cannot be reconciled to a proven baseline, stop and report the discrepancy; do not set a lower floor silently.
3. Bind the actual private library inventory artifact by SHA256 and declare the exact extractor revision. Keep all inputs and outputs private. Run scripts.atlas_generation_review with baseline-db, baseline-proof, current-db, current-proof, inventory, inventory-sha256, extractor-revision, minimum-baseline-pages, output. This command is offline, read-only on inputs, no network or OCR.
4. The report distinguishes changed/missing historical rows even when totals match; duplicates are counted. Resource ID multiplicity, existing resource-ID/hash associations and document identity multiplicity must also survive; previously unhashed resources may gain a hash, while changed historical associations are held for reconciliation. Page identities with no document row remain unresolved. Review known page ranges and blank pages; hold conflicting/failed or unknown-count documents. No extraction authorization is granted by this ledger. Unhashed resources remain in review. The archive hash binds bytes, not inventory semantics, role completeness or collector freshness. Caller must verify both exports are the same catalogue and the revision is correct.
5. HOLD_BASELINE_REGRESSION returns exit code 2 after writing a private review report. No automatic repair. A complete text-coverage result is still not official cadastre verification, acceptance of the nine archive roles, resolution of 131 historical pending documents, geographic/rights verification, authenticated site QA, or authorization to publish.
6. CI exercises real SQLite Backup API on synthetic fixtures. Actual Mac execution and integration with the installed catalogue/FTS schema remain a separate gate. If the installed schema differs from resources/documents/pages, establish explicit reviewed mapping rather than guessing.
